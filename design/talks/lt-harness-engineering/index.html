01 / INTRO

念能力を自由に作るために、
AIの仕事に枠を作る。

TRPGのシステム制作 × ハーネスエンジニアリング

HUNTER×HUNTER 非公式TRPGの制作実例

ルールを書く・確かめる・試す・見直す。
その一周を、リポジトリに組み込んでいる。

02 / PROBLEM

「好きな能力を作れる」は、
ルールを作る側には難しい。

TRPG＝会話と判定で物語を進めるゲーム

自由な能力設計

同じ能力原理の応用？
それとも別の独立効果？

複数ルールの接続

射程・行動・消費・持続。
単独では読めても、組むと曖昧。

必要なのは、文章量だけでなく「裁定できる一貫性」。

03 / DEFINITION

ハーネス＝
AIが作業を進めるための環境。

この発表での使い方

指示・制約→参照する正本→検証と記録

何を読んで、どこまで変え、
何をもって確認済みとするかを置く。

このプロジェクトでは、Markdown・Python・GitHubで構成。

04 / GUARDRAILS

「変えてよい」を明文化する。

創造性を残しながら、決定権を揃える

AIが進められる

表現の整理・例示
不足処理の「暫定補足」

人間と相談して採用

既存の数値・設計方針の変更
Issueで提案と影響を記録

AGENTS.md ＋ 制作スキル ＋ 運用ガイド

保存原文は固定。遊ぶための正本は rules/。

05 / CHECKS

確かめ方を、3つに分ける。

同じ「検証済み」でまとめない

機械検証

原文ハッシュ・55節の対応
リンク・サンプル数値

整合性を繰り返し確認
AI模擬試遊

行動・裁定・状態変化
境界ケースと導入シナリオ

進行時の曖昧さを発見
人間の実卓

楽しさ・理解しやすさ
全体バランス・所要時間

現時点では未実施

AIが宣言してから、ツールでダイス。出目と計算を残す。

06 / FEEDBACK

試遊の成果は、
「要調整」を持ち帰れたこと。

初回AI試遊で見つかった実例

観測：距離が曖昧

「同じ部屋」と「移動区画」の
距離区分がはっきりしない。

記録から検討へ

試遊課題 T01 を
距離の暫定補足 A12 に統合。

試遊ログ→課題・Issue→合意・反映・再検証

Issueの作成だけでは、採用・解決扱いにしない。

07 / LIMITS

確認できたことと、
まだ言えないことを分ける。

自動化した範囲を、成果として説明する

できていること

本文とサンプルの機械検証
試遊の出目・裁定・状態の記録
push時のCIによる再確認

残っていること

AI試遊の結論は「要調整」
単一AIでの秘密情報隔離に限界
人間の実卓・全体バランスは未確認

08 / TAKEAWAY

自由なルール制作を、
検証できる仕事にする。

このプロジェクトからの学び

AIに渡すのは、依頼文だけでなく
正本・変更権限・確かめ方・戻し先。

この組み合わせが、TRPG制作のハーネスになっている。
